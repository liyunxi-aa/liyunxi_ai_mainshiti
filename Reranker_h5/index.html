🔄 Reranker 重排序

大模型检索系统中的精排引擎 — 从粗筛到精排，用 Cross-Encoder 深度理解 Query-Document 相关性

两阶段检索：Retriever → Reranker

在现代 RAG（检索增强生成）系统中，检索不是一步到位的。粗筛（Retriever）用轻量级 Bi-Encoder 从海量库中快速召回 Top-K 候选，再由精排（Reranker）用更强的 Cross-Encoder 对候选进行深度重排，最终输出 Top-N 最相关的文档给 LLM。

📐 两阶段检索引擎公式

💡 核心直觉：Bi-Encoder 分别编码 Query 和 Document，通过向量内积计算相似度——快但粗糙（Query 和 Doc 在编码时互不可见）。Cross-Encoder 将 Query 和 Document 拼接后一起送入模型，让它们的 Token 在每一层 Transformer 中充分交互——慢但精准。两阶段策略恰好取长补短：粗筛用快方法缩小范围，精排用强方法精细排序。

Bi-Encoder vs Cross-Encoder

理解 Reranker 的关键在于区分两种编码架构。Bi-Encoder独立编码 Query 和 Doc，然后通过点积计算分数；Cross-Encoder将两者拼接后联合编码，实现 Token 级别的交叉注意力。

🔷 Bi-Encoder（双塔）

Query 和 Document 独立编码为向量，通过余弦相似度/点积计算相关性。

✅ 离线预计算 Doc 向量，在线仅算 Query
✅ 百万级文档毫秒级检索（ANN 近似最近邻）
❌ Query 和 Doc 编码时互不可见，缺乏细粒度交互

🟡 Cross-Encoder（交叉编码）

Query 和 Document 拼接后共同输入模型，每层 Transformer 都进行交叉注意力。

✅ Query-Doc Token 级交互，捕捉精确语义匹配
✅ 对近义词、同义改写、长尾查询泛化更强
❌ 无法预计算——每对 Query-Doc 都要完整推理一次

🔬 两种编码方式的计算复杂度对比

💡 为什么 Cross-Encoder 更准？在 Bi-Encoder 中，Query "苹果" 和 Document "iPhone 最新发布会" 分别编码时，"苹果"可能被编码偏向"水果"方向。而在 Cross-Encoder 中，Query 和 Document Token 在同一上下文中交互，模型能从"发布会"推知"苹果=Apple公司"。这就是上下文感知的相关性判断。

💡 推理成本分析：对于一个 Query，若 Retriever 召回 K=100 篇文档，Reranker 需要对 100 个 (Query, Doc) 对分别执行 Cross-Encoder 推理——每对都要完整过一遍 Transformer。这是 Reranker 的计算瓶颈，也是为什么K 不能太大的根本原因。实践中通常 K=20~100，N=3~10。

分数融合：线性加权与 Reciprocal Rank Fusion

实际系统中，Reranker 分数不一定完全替代粗筛分数。常见做法是将多路信号融合——Bi-Encoder 的语义相似度、Cross-Encoder 的相关性分数、BM25 的词汇匹配分数、甚至是 URL PageRank 等信号按权重混合，得到最终排序分数。

📐 线性加权融合

📐 Reciprocal Rank Fusion (RRF)

✅ 线性加权融合
适合分数同尺度的场景（如都已归一化到 0~1）。调节 α 可控制各信号占比。问题：不同 Reranker 的分数分布差异大，直接加权可能导致某个信号主宰最终排序。
✅ RRF 排序融合
不依赖分数绝对值——只使用排名位置。k 是平滑常数（通常 k=60）。极其鲁棒：即使某个 Reranker 给某文档打了极端高分，在 RRF 中也只贡献排名信息。多系统融合首选。

级联重排：多阶段漏斗

在大规模 RAG 系统中，通常不止两阶段——而是多级漏斗：从海量文档到最终少而精的上下文，每一级都更贵但更准。这就是级联重排（Cascade Reranking）的核心思想。

Reranker 在 RAG Pipeline 中的角色

Reranker 不只是"把排序弄准一点"——它是连接检索和生成的关键桥梁，直接影响 LLM 的生成质量。

📐 Reranker 对生成质量的影响

粗筛 Top-5 直接给 LLM

✅ 有 Reranker
精排 Top-5 给 LLM

🚀 Reranker + 融合
多路融合精排

🧠 LLM-as-Reranker
LLM 直接精排
零样本，理解复杂指令，但延迟和成本最高
💡 关键洞察：Reranker 本质上是在用计算换上下文质量。在 RAG 中，LLM 的输入上下文窗口是有限且昂贵的——必须确保每一篇送入 LLM 的文档都是高质量的。Reranker 承担了"守门员"角色：宁可多花 100ms 做精排，也不要浪费 LLM 宝贵的上下文窗口在无关文档上。研究表明，经过 Reranker 精排后，RAG 生成质量可提升 20%~40%（以 RAGAS 指标衡量）。
