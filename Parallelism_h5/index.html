并行训练：数据并行 vs 模型并行

大模型怎么放进显卡里？一文彻底看懂

数据并行：模型完整，数据分开   🆚   模型并行：模型切开，数据一起

一、数据并行 (Data Parallel) 最常用/最简单

一句话：每张显卡都放 完整模型，每张显卡算 不同数据。

怎么做？

  • 显卡 A：放完整模型 → 算数据 A (Batch 1)
  • 显卡 B：放完整模型 → 算数据 B (Batch 2)
  • 显卡 C：放完整模型 → 算数据 C (Batch 3)

最后把梯度汇总，一起更新模型。

✅ 优点

  • 简单、速度快。中小模型默认使用。

❌ 缺点

  • 当 模型太大时，一张卡连一个完整的模型都装不下 → 不能用！

二、模型并行 (Model Parallel) 大模型专用

一句话：一张卡放不下完整模型，把模型切开，分给多张卡。

1. 纵向切：流水线并行 (Pipeline Parallel)

  • 按层切：前两层放卡1，中间几层放卡2，最后几层放卡3。
  • 像工厂流水线一样接力跑：卡1算完传给卡2，卡2算完传给卡3。

2. 横向切：张量并行 (Tensor Parallel)

  • 把一层切开：一个巨大的矩阵太大，切成几块。
  • 比如把 1个巨大的矩阵乘法，拆给 4张卡 同时算，再把结果拼起来。

🔥 面试必考：串联对比 & 流水线调度策略

Data Parallel (数据并行)
多卡存完整模型，各卡算不同数据，最后汇总梯度
👉 适合小模型、速度快
Model Parallel (朴素模型并行)
单卡放部分层，同一 batch 完整串行过各卡
👉 大模型能用，但利用率极低（没算到的卡都在闲置）
Pipeline Parallel (流水线并行)
模型分层 + 数据切分为 Micro-batch (微批次) 流水线接力
👉 超大模型训练主流，利用率大幅提升

常见调度策略 (Pipeline Schedules)

  • 1. GPipe (Google): （即用上面的气泡图策略）
    先把所有的微批次 (micro-batch) 的前向传播跑完，再统一跑它们的反向传播。
    ✓ 优点：实现相对简单，逻辑清晰。
    ✗ 缺点：显存占用极大！必须把所有 micro-batch 产生的前向激活值一直存在显存里，直到跑完对应反向才能释放。

    一旦跑完一个 micro-batch 的前向，立刻接着跑它的反向传播，之后再跑下一个前向。
    ✓ 优点：只要跑完反向，前面的激活值就能马上释放，显存非常省，且利用率高。
    👉 现状：现在的绝对主流！(Megatron-LM, DeepSpeed, PyTorch 默认策略)。
  • 3. Interleaved 1F1B (交错 1F1B):
    把模型切分成更多的阶段（比 GPU 数量多），比如 4 张卡被切成 8 块，卡间交替执行这些小块的 1F1B。
    ✓ 优点：进一步缩减了开头的 Bubble (闲置气泡) 时间。
    ✗ 缺点：计算逻辑复杂，多出很多额外的通信开销，极大规模模型才可能会上。
