🧊 1-Bit 量化 · 大模型极限压缩

从 FP16 到 ±1：权重二值化 / 三值化的原理、主流方案与端侧部署实战

1. 为什么需要 1-Bit 量化？

大语言模型参数动辄 7B–70B，FP16 精度下 7B 模型需要 ~14GB 显存，无法在消费级设备运行。 量化的核心思想：用极少比特数表示每个权重，极限就是 1 比特——每个权重仅占 1 bit，取值 {−1, +1}（或加 0 变为三值）。

📐 量化压缩比

💡 极限压缩：从 FP16 (16 bit/weight) 压到 1.58 bit（三值），压缩比 ≈ 10×； 纯 1 bit（二值 {−1,+1}），压缩比 = 16×。8B 模型仅需 ~1.15GB，iPhone 可实时推理。

2. 两条路线：1 比特 vs 1.58 比特

业界「1-Bit LLM」实际分两支：纯 1 比特（二值 {−1,+1}）和1.58 比特（三值 {−1,0,+1}）。 加一个 0 值（稀疏化）能极大稳定训练，是当前工程上的最优平衡点。

维度 纯 1-Bit（二值） 1.58-Bit（三值）
权重取值 {−1, +1} {−1, 0, +1}
每权重比特数 1.0 bit 1.58 bit
压缩比 (vs FP16) 16× ~10×
训练难度 极高（易崩溃） 中等（0 值缓冲）
推理性能 略低于全精度 接近全精度
代表方案 Bonsai, OneBit BitNet b1.58
适用场景 极致端侧（手机/嵌入式） 通用 CPU 推理 / 服务器
💡 为什么主流是 1.58 bit？纯 ±1 太激进：sign 函数直接抹掉所有幅度信息，训练容易发散。 加一个 0（稀疏连接）给模型留了「不表达」的自由度，大幅稳定训练，且平均每权重仅 1.58 bit，工程上最划算。

3. BitNet b1.58 — 工业级三值量化

微软 BitNet b1.58 是最成熟的 1-bit 级 LLM 方案。权重约束为 {−1, 0, +1}， 使用 BitLinear 替代标准 nn.Linear，从头训练（非 PTQ 后量化），2B 模型仅 0.4GB。

5. 核心技术：STE 与混合精度训练

1-bit 量化的核心挑战：sign() 函数导数几乎处处为 0，梯度无法回传。 解决方案是 STE（Straight-Through Estimator）：前向用硬量化，反向直接拷贝梯度。

📐 STE 梯度估计

// 1-Bit 量化训练伪代码 (PyTorch 风格) class BitLinear(nn.Module): def forward(self, x): // 1. 权重量化 (前向: 硬量化) alpha = self.W.abs().mean(dim=-1, keepdim=True) W_q = sign(self.W) * alpha // 纯 1-bit: {−α, +α} // 或三值: W_q = round(clip(self.W/alpha, −1, 1)) * alpha // 2. 激活动态量化 (8-bit) x_q = quantize_8bit(x, block_size=128) // 3. 低精度矩阵乘法 out = W_q @ x_q // 4. 反向传播时 W_q.grad = W.grad (STE 直通!) return out + self.bias // STE 实现: 前向用量化值, 反向传梯度给全精度权重 def ste_quantize(w, bits=1): w_q = quantize(w, bits) // 硬量化: sign() 或 round() return w + (w_q - w).detach() // 前向=w_q, 反向梯度流过 w
💡 STE 的直觉：前向传播时，量化函数像一个「硬开关」，输出确切的 ±1/0； 但反向传播时，梯度直接穿过量化函数（当成恒等映射），更新底层的全精度权重副本。 这样模型始终维护一份 FP16 的 latent weights，训练稳定且质量高。
