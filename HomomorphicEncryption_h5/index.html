🔐 同态加密 · Homomorphic Encryption

从 RSA 乘性同态到 Gentry 全同态蓝图，再到 CKKS/TFHE 现代方案——在不解密的情况下对密文做任意计算。

1. 什么是同态加密

同态加密（Homomorphic Encryption, HE）允许直接在密文上执行运算，解密后得到的结果与在明文上执行相同运算的结果一致。 它的核心特性是：Enc(m₁) ⊗ Enc(m₂) = Enc(m₁ ⊕ m₂)，其中 ⊗ 是密文空间的运算，⊕ 是明文空间的运算。

💡 核心张力——噪声 vs 计算深度：所有基于格的 HE 方案都在密文中嵌入噪声。 每次运算（尤其是乘法）会使噪声指数增长；当噪声超过阈值时解密失败。 Bootstrapping（自举） 是同态地执行解密电路，将噪声"刷新"回初始水平，从而实现无限深度计算。

2. 数学基础 — LWE 与 RLWE

现代 HE 方案的安全基础是 LWE（Learning With Errors） 及其环变体 RLWE（Ring-LWE）—— 给定随机矩阵 A 和含噪声的内积 b = As + e，恢复秘密向量 s 在计算上不可行（量子计算机也无法高效求解）。

📐 LWE 问题

LWE 的困难性可归约到格上最坏情况的困难问题（如 GapSVP），这是 Regev 2005 年的核心成果。

📐 RLWE 问题

RLWE 将矩阵换为多项式环，利用 NTT（数论变换）将计算复杂度从 O(n²) 降至 O(n log n)。

📐 基于 RLWE 的对称同态加密（最简方案）

💡 噪声增长是关键瓶颈：加法使噪声 + 噪声（线性增长），乘法使噪声 × 噪声（指数增长）。 因此 乘法深度 决定了方案是 PHE、SWHE 还是需要 Bootstrapping 的 FHE。

3. PHE 部分同态加密 — 经典方案

在 FHE 出现之前，已有多个公钥密码系统天然支持单一同态运算。 尽管只能做加法或乘法，这些方案在电子投票、隐私保护数据聚合等场景中已得到广泛应用。

🔐 RSA — 乘性同态

// RSA 乘性同态 Enc(m₁) = m₁ᵉ mod N Enc(m₂) = m₂ᵉ mod N Eval: Enc(m₁)×Enc(m₂) = (m₁m₂)ᵉ mod N = Enc(m₁ × m₂) ✓ // 注意：RSA 不支持加法同态

🔐 Paillier — 加性同态

// Paillier 加性同态 Enc(m₁) = gᵐ¹ r₁ⁿ mod N² Enc(m₂) = gᵐ² r₂ⁿ mod N² Eval: Enc(m₁)×Enc(m₂) = gᵐ¹⁺ᵐ²(r₁r₂)ⁿ mod N² = Enc(m₁ + m₂) ✓ // 标量乘法: Enc(m)ᵏ = Enc(k×m)

⚖️ PHE 方案对比

方案同态运算安全基础密文膨胀率典型应用

💡 PHE 虽有限但非常实用：Paillier 加密在联邦学习（Secure Aggregation）中广泛使用——各方上传 Enc(gradient)， 服务器聚合得到 Enc(sum)，解密后分发平均梯度。整个过程服务器从未见过任何单独的梯度。

4. BFV / BGV — Leveled 全同态方案

BFV (Brakerski-Fan-Vercauteren) 和 BGV (Brakerski-Gentry-Vaikuntanathan) 是第二代 HE 方案， 支持有限深度的混合加乘运算。它们基于 RLWE，将明文编码为多项式环 R_t = ℤ_t[x]/(xⁿ + 1) 中的元素。

5. FHE — 全同态加密与 Bootstrapping

Craig Gentry 2009 年博士论文首次构造了全同态加密方案，核心创新是 Bootstrapping（自举）—— 同态地执行自身的解密电路，将噪声重置到初始水平，从而支持无限深度计算。

📐 Gentry's Bootstrapping 定理

1
加密计算
密文 c = Enc(m) 逐层计算，噪声从 η₀ 增长到 η_max
2
噪声逼近阈值
当 noise > q/(4t) 时解密即将失败
3
Bootstrapping
同态计算 Dec(c, Enc(sk)) → Enc(m) 噪声 = η₀
4
继续计算
噪声重置后继续下一层计算

💡 Bootstrapping 的代价：一次 Bootstrapping 约等于 100-1000 次普通乘法（在 TFHE 中优化到 ~10ms）。 现代 FHE 编译器的核心优化就是最小化 Bootstrapping 次数——通过调度计算顺序、合并操作、选择最优参数。

6. CKKS — 近似同态加密（浮点数）

CKKS (Cheon-Kim-Kim-Song, 2017) 专为近似实数运算设计，是机器学习推理中最常用的 HE 方案。 与 BFV/BGV 的精确整数运算不同，CKKS 将明文视为带有噪声的浮点数——这恰好契合了神经网络的低精度容忍特性。

🎯 CKKS 的 SIMD 特性

CKKS 天然支持 SIMD（单指令多数据）：一个密文可打包 N/2 个浮点数，一次密文乘法 = N/2 路并行的实数乘法。

// CKKS SIMD: 一个密文 = 最多 16,384 个 slots (N=32,768) encoder.encode([1.0, 2.0, 3.0, ..., 4096.0], scale: 2^40) → 明文多项式 p₁(x) encoder.encode([0.5, 1.5, 2.5, ..., 4095.5], scale: 2^40) → 明文多项式 p₂(x) evaluator.multiply(ct₁, ct₂) → ct₃ decrypt(ct₃) → [0.5, 3.0, 7.5, ...] // elem-wise 乘法! // 旋转操作 (Rotation): 循环移位 1 位 evaluator.rotate(ct, 1) → ct' decrypt(ct') → [2.0, 3.0, 4.0, ..., 4096.0, 1.0]
💡 为什么 CKKS 是 ML 推理首选：神经网络天然容忍低精度（fp16/int8），CKKS 的近似误差（~2⁻³⁰）远小于量化误差。 SIMD 并行使得一层卷积/全连接 = 几次密文乘加，理论吞吐可达 百万次加密操作/秒（在 GPU 加速下）。

7. TFHE — 超快 Bootstrapping（每门 ~10ms）

TFHE (Chillotti et al., 2016-2020) 将 Bootstrapping 优化到了极致——每次逻辑门计算后进行自举， 并且将可编程自举（PBS, Programmable Bootstrapping）同时用作查表运算，实现任意函数的同态计算。
