💡 从提示工程到推理策略

大语言模型（LLM）在直接回答复杂推理问题时，常常产生"一步到位"式的错误答案——模型在单次前向传播中试图直接从输入跳到输出，缺乏中间推理步骤的显式引导。

Chain-of-Thought（思维链）和 Tree-of-Thoughts（思维树） 是两种关键的推理增强技术，核心思想是：让模型把推理过程"说"出来，并在推理空间中搜索最优路径。它们分别代表了从线性推演到树形分支搜索的思维跃迁。

🔗 Chain-of-Thought（思维链）

核心思想

Chain-of-Thought（CoT）由 Wei et al. (2022) 提出，核心思想是：在 prompt 中提供逐步推理的示例（few-shot），或直接指示模型"让我们一步一步思考"（zero-shot），引导模型生成中间推理步骤后再给出最终答案。

🔑 关键洞察： 当 LLM 被要求 "逐步输出" 推理过程时，每个后续 token 都能"关注到"前面已经推导出的中间结果——这相当于在每个推理步骤上都做了一次隐式的检索/复核，让模型有更多机会纠正初始直觉的偏差。

数学直觉

标准自回归生成是直接最大化：

$$P(\text{answer} \mid \text{question})$$

而 CoT 将推理过程显式分解为中间步骤序列 \(z_1, z_2, \dots, z_k\)，再基于这些步骤得出答案：

$$P(\text{answer} \mid \text{question}) = \sum_{z_1, \dots, z_k} P(\text{answer} \mid z_k, \dots, z_1, \text{question}) \cdot \prod_{t=1}^{k} P(z_t \mid z_{<t}, \text{question})$$

这种分解使模型能在每个子问题上分配单独的"计算预算"，从而显著提升复杂推理的准确率。

🧩 CoT 变体：Few-Shot · Zero-Shot · Auto-CoT

📋 Few-Shot CoT

在 prompt 中手写 2-8 个包含详细推理步骤的示例，模型通过上下文学习（In-Context Learning）模仿推理模式。

示例 prompt：
Q: 小明有 3 个苹果，又买了 4 个...
A: 第一步... 第二步... 最终 7 个。
Q: <实际提问>
A:

✅ 效果最稳定  |  ❌ 需要人工编写高质量示例

🪄 Zero-Shot CoT

不需要示例，只需在问题末尾追加一句 "Let's think step by step"，就能触发模型输出推理链。

Q: 小明有 3 个苹果，又买了 4 个...
Let's think step by step.
Step 1: ... Step 2: ... Therefore...

✅ 零成本部署  |  ❌ 对指令措辞较敏感

🤖 Auto-CoT（自动思维链）

由 Zhang et al. (2023) 提出：自动从问题库中聚类抽取出多样化的示例问题，再对每个示例问题用 Zero-Shot CoT 生成推理链，最终构造出无需人工标注的 Few-Shot prompt。

⚙️ CoT 为什么有效？

Cot 有效的原因可以从几个角度解释：

  1. 计算预算扩展： Transformer 中每个 token 的计算量是固定的（一次前向传播），CoT 通过生成更多中间 token，相当于增加了处理该问题的总 FLOPs，从而提升了模型的"思考深度"。
  2. 中间结果可被注意力利用： 自回归生成时，后续 token 可以通过注意力机制"看到"前面推导出的所有中间结果。这相当于模型在推理过程中不断复核自己的推导，减少了累积错误。
  3. 语言即推理媒介： 预训练语料中包含大量人类书写的推理过程（数学证明、解题步骤、逻辑推导等），CoT 的格式触发了模型对这些推理模式的模仿。
  4. 错误回溯： 如果推理链中某一步出错，模型在后续步骤中有一定概率进行自我纠正——这在直接输出中是不可能的。
📊 实验证据： 在 GSM8K 数学推理基准上，PaLM 540B 使用 CoT 将准确率从约 17% 提升到 58%；在 StrategyQA 上提升幅度同样显著（约 +20pp）。模型规模越大，CoT 的增益越突出——这是一种涌现能力。

🌳 Tree-of-Thoughts（思维树）

从链到树：为什么需要分支？

CoT 的本质是线性推理：一条路走到黑。但人类解决困难问题时，往往会在关键节点上"想出几个不同的方向，逐一评估，选择最有希望的方向继续探索"。这就如同下棋——棋手不会只算一条线，而是在头脑中展开一棵"搜索树"。

Tree-of-Thoughts（ToT） 由 Yao et al. (2023) 提出，将 LLM 的推理建模为在思维空间中的树搜索——每个"思维节点"是一段文本（一个中间想法），模型同时扮演生成器（产生下一步候选思维）和评估器（判断每个思维的价值）。

🧭 ToT 搜索策略详解

ToT 的搜索策略是经典 AI 搜索算法（BFS/DFS）与大语言模型的结合。核心区别在于：传统搜索中，状态转移函数是确定性的；ToT 中，状态扩展（生成候选思维）和状态评估都由 LLM 完成。

策略 核心机制 优点 缺点 适用场景
BFS
广度优先		 每层生成 b 个候选思维，保留价值最高的 Top-k 个，再展开下一层 不易陷入局部最优，全局性好 每层调用 LLM 次数多（b×评估次数），token 成本高 创造性写作、方案设计等需要多样性的任务
DFS
深度优先		 每次只沿当前最优路径深入探索，直到叶节点或评估分数过低时回溯 快速到达可行解，token 消耗较少 可能陷入死胡同，需要强启发式函数 数学证明、代码调试等纵向深度重要的任务
Beam Search 每层保留 n 条最候选路径同时推进；可视为"受限 BFS" BFS 的高效替代，在成本和多样性间取得平衡 Beam 内路径可能趋向同质化 通用推理（ToT 论文中在 24 点任务上使用 b=5）

状态评估的两种模式

📏 价值评估 (Value)

LLM 对每个候选思维独立打分，如 "sure/ likely/ impossible"（确定/可能/不可能）或 1-10 分。保留得分高的思维。

Prompt:
Evaluate if this partial solution is promising (sure/likely/impossible)...
→ likely (score: 0.7)

💰 成本：每个候选 1 次 LLM 调用

🗳️ 投票评估 (Vote)

LLM 在多个候选思维中投票选出最优的，天然实现排序和筛选。

Prompt:
Given these 5 candidate next steps, which is the best?...
→ Step 3 is the best, Step 1 is runner-up

💰 成本：每次投票比较 n 个候选

🧪 实验结果： 在 24 点游戏中，标准提示（IO prompt）准确率仅 7.3%，CoT 为 4.0%（此问题上 CoT 不如 IO），而 ToT（b=5, 每层保留 5 个候选）达到 74%。在创造性写作任务中，人类评估者也普遍偏好 ToT 的输出。

⚖️ 思维链 vs 思维树：全面对比

维度 🔗 Chain-of-Thought 🌳 Tree-of-Thoughts
推理结构 线性链式（1→2→3→...→答案） 树形分支（每个节点可有多条出边）
搜索方式 无搜索（贪婪解码 / 温度采样） 显式搜索（BFS / DFS / Beam Search）
状态评估 不评估中间状态 每步评估思维价值，剪枝低分路径
回溯能力 弱 — 偶尔自纠正，但不可回退 强 — 可在任意节点回溯到祖先状态
LLM 调用量 1 次调用（1 条完整推理链） 多次调用（生成 + 评估 × 搜索步数）
Token 开销 低（≈1×输出长度） 高（可能 10-100×于 CoT）
适用场景 算术推理、常识问答、简单逻辑题 复杂规划、数学搜索、创造性写作、博弈决策

💻 代码实践：LangGraph 实现 CoT 与 ToT

在实际工程中，CoT、ToT 等推理策略可以通过 LangGraph 来编排。LangGraph 是 LangChain 生态中的图状态机框架，专为构建有循环、分支、条件路由的 LLM 应用而设计。下面通过两个实例演示如何用 LangGraph 实现 CoT 和 ToT。

示例 1：LangGraph 实现 Chain-of-Thought 线性推理

用 LangGraph 搭建一个「思考 → 输出答案」的简单链式推理图。这是最基础的 CoT 模式——模型先生成推理步骤，再基于推理给出最终答案。

python cot_langgraph.py 
from typing import TypedDict
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI

# ── 1. 定义状态：图中流转的数据结构 ──
class CoTState(TypedDict):
    question: str
    reasoning: str           # 中间推理步骤
    answer: str              # 最终答案
    step_count: int          # 已执行的推理步数

llm = ChatOpenAI(model="gpt-4o", temperature=0.3)

# ── 2. 定义节点 Nodes ──
def think(state: CoTState) -> CoTState:
    """思考节点：生成一步推理"""
    prompt = f"""请对以下问题进行逐步推理。当前是第 {state['step_count'] + 1} 步。
问题：{state['question']}
已有的推理：{state['reasoning'] or '（无）'}
请输出下一步推理（一句话即可）："""
    response = llm.invoke(prompt)
    new_reasoning = (state["reasoning"] + "\n" + response.content).strip()
    return {**state, "reasoning": new_reasoning, "step_count": state["step_count"] + 1}

def conclude(state: CoTState) -> CoTState:
    """总结节点：基于所有推理步骤输出最终答案"""
    prompt = f"""基于以下推理过程，给出最终答案。
问题：{state['question']}
推理过程：{state['reasoning']}
最终答案："""
    response = llm.invoke(prompt)
    return {**state, "answer": response.content}

# ── 3. 条件路由 ──
def should_continue(state: CoTState) -> str:
    """判断是否需要继续思考，还是已经可以输出答案"""
    if state["step_count"] >= 4:
        return "conclude"       # 最多 4 步推理，然后强制总结
    # 让 LLM 自行判断是否推理充分
    check = llm.invoke(f"推理是否已足够回答问题？只回复 YES 或 NO。\n推理：{state['reasoning']}")
    return "conclude" if "YES" in check.content.upper() else "think"

# ── 4. 构建图 ──
builder = StateGraph(CoTState)
builder.add_node("think", think)
builder.add_node("conclude", conclude)
builder.set_entry_point("think")
builder.add_conditional_edges("think", should_continue, {"think": "think", "conclude": "conclude"})
builder.add_edge("conclude", END)

app = builder.compile()

# ── 5. 运行 ──
result = app.invoke({"question": "如果今天是星期二，100 天后是星期几？", "reasoning": "", "answer": "", "step_count": 0})
print("推理过程:", result["reasoning"])
print("最终答案:", result["answer"])
💡 关键设计： 条件边 should_continue 实现了自适应推理深度——简单问题 1-2 步即可得出结论，复杂问题则自动扩展推理步数。这比固定步数的 prompt 更灵活。

示例 2：LangGraph 实现 Tree-of-Thoughts BFS 搜索

接下来是一个更复杂的 ToT 实现：每层并行生成多个候选思维 → 独立评估 → 保留 Top-k → 进入下一层。这模拟了 ToT 论文中的 BFS 搜索策略。

python tot_langgraph.py 
from typing import TypedDict, List
from dataclasses import dataclass
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI

# ── 数据结构 ──
@dataclass
class Thought:
    content: str
    score: float = 0.0

class ToTState(TypedDict):
    problem: str
    current_layer: List[Thought]     # 当前层的候选思维
    best_path: List[str]             # 记录最优路径
    layer_idx: int                   # 当前搜索深度
    max_layers: int                  # 最大深度

llm = ChatOpenAI(model="gpt-4o", temperature=0.8)

# ── 节点 1: 思维生成 ──
def generate_thoughts(state: ToTState) -> ToTState:
    """给定当前最优思维，生成 k 个候选下一步思维"""
    k = 3  # 每层生成 3 个候选
    candidates: List[Thought] = []

    for i in range(k):
        prev_best = state["best_path"][-1] if state["best_path"] else "（起始）"
        prompt = f"""问题：{state['problem']}
当前最优思路：{prev_best}
请提出一个不同的下一步思考方向（候选 {i+1}）："""
        resp = llm.invoke(prompt)
        candidates.append(Thought(content=resp.content))

    return {**state, "current_layer": candidates}

# ── 节点 2: 状态评估 ──
def evaluate_thoughts(state: ToTState) -> ToTState:
    """对每个候选思维独立打分（1-10），保留最高分的一个"""
    for t in state["current_layer"]:
        prompt = f"""问题：{state['problem']}
当前思路：{t.content}
请评估该思路的可行性，给出 1-10 的分数。只输出数字。"""
        resp = llm.invoke(prompt)
        try:
            t.score = float(resp.content.strip())
        except ValueError:
            t.score = 5.0  # 解析失败给默认分

    # 排序，选择最高分
    state["current_layer"].sort(key=lambda t: t.score, reverse=True)
    best = state["current_layer"][0]

    return {
        **state,
        "best_path": state["best_path"] + [best.content],
        "layer_idx": state["layer_idx"] + 1,
    }

# ── 节点 3: 最终综合 ──
def synthesize(state: ToTState) -> ToTState:
    """搜索结束后，基于最优路径给出最终答案"""
    path_str = "\n".join(f"{i+1}. {s}" for i, s in enumerate(state["best_path"]))
    prompt = f"""问题：{state['problem']}
搜索到的最优推理路径：{path_str}
请基于以上路径给出最终答案："""
    resp = llm.invoke(prompt)
    return {**state, "best_path": state["best_path"] + [f"🎯 最终答案: {resp.content}"]}

# ── 条件路由 ──
def should_continue(state: ToTState) -> str:
    if state["layer_idx"] >= state["max_layers"]:
        return "synthesize"
    return "generate"

# ── 构建图 ──
builder = StateGraph(ToTState)
builder.add_node("generate", generate_thoughts)
builder.add_node("evaluate", evaluate_thoughts)
builder.add_node("synthesize", synthesize)

builder.set_entry_point("generate")
builder.add_edge("generate", "evaluate")
builder.add_conditional_edges("evaluate", should_continue, {
    "generate": "generate",
    "synthesize": "synthesize",
})
builder.add_edge("synthesize", END)

app = builder.compile()

# ── 运行 ──
result = app.invoke({
    "problem": "设计一个能减少城市交通拥堵的方案",
    "current_layer": [],
    "best_path": [],
    "layer_idx": 0,
    "max_layers": 3,
})
print("\n".join(result["best_path"]))
🧠 BFS vs DFS 切换： 上述实现是 BFS（每层横向扩展多个候选再剪枝）。若改为 DFS，只需在 generate_thoughts 中将 k=1、替换为"沿当前最优方向深入挖掘"的 prompt 即可。这种灵活性正是 LangGraph 图编排的优势。

Graph-of-Thoughts (GoT)

由 Besta et al. (2023) 提出：如果"树"还不够表达——思维之间可以是任意图结构。GoT 允许思维节点之间进行合并（combine）、细化（refine）、聚合（aggregate）等操作，将多个推理链的结论融合成更强的中间状态。

Algorithm-of-Thoughts (AoT)

由 Sel et al. (2023) 提出：与其让 LLM 在外部进行搜索（并反复调用自身），不如直接在模型的一次前向传播中模拟搜索过程。AoT 在 prompt 中嵌入算法式指令（如 "首先探索 X…若不行则回溯到 Y…"），利用 LLM 的上下文学习能力将搜索"内化"为自动生成的过程。

📊 对比： AoT 比 ToT 节省大量 LLM 调用次数（无需外部搜索循环），但要求模型有较强的指令跟随与上下文推理能力。实验显示 AoT 在 24 点任务上的性能与 ToT 接近，但 token 使用效率高出数倍。

🤖 代码实践：LangGraph 实现循环推理代理

在工程中，上述这些图思维或者树搜索，通常可以通过 LangGraph 这类框架来实现状态流转和条件路由。

python langgraph_reasoning_agent.py 
from typing import TypedDict, List
from langgraph.graph import StateGraph, END
from langchain_openai import ChatOpenAI

# 1. 定义状态: 图中需要流转的数据结构
class GraphState(TypedDict):
    question: str
    thoughts: List[str]
    is_resolved: bool

llm = ChatOpenAI(model="gpt-4", temperature=0.7)

# 2. 定义节点 (Nodes)
def think_node(state: GraphState):
    """节点：生成一个新的推理步骤/想法"""
    q = state["question"]
    thoughts = "\n".join(state["thoughts"])
    prompt = f"问题: {q}\n以前的想法: {thoughts}\n请输出下一个合乎逻辑的想法："
    
    response = llm.invoke(prompt)
    state["thoughts"].append(response.content)
    return state

def evaluate_node(state: GraphState):
    """节点：评估当前想法是否解决了问题"""
    prompt = f"判断以下想法是否已经完美解决了问题，只需回答 YES 或 NO：\n{state['thoughts'][-1]}"
    response = llm.invoke(prompt)
    state["is_resolved"] = "YES" in response.content.upper()
    return state

# 3. 定义条件边 (Conditional Edges)
def should_continue(state: GraphState):
    """路由函数：决定下一步走向"""
    if state["is_resolved"]:
        return END # 问题解决，结束图流转
    elif len(state["thoughts"]) > 5:
        return END # 超出最大搜索深度，强制结束
    else:
        return "think" # 继续思考循环

# 4. 构建并编译状态图
workflow = StateGraph(GraphState)

workflow.add_node("think", think_node)
workflow.add_node("evaluate", evaluate_node)

workflow.set_entry_point("think")
workflow.add_edge("think", "evaluate")
workflow.add_conditional_edges(
    "evaluate", 
    should_continue
)

app = workflow.compile()

# 运行图流转
result = app.invoke({"question": "24点算法：使用 4, 9, 8, 4 算出 24", "thoughts": [], "is_resolved": False})
print("最终推理路径:", result["thoughts"])
