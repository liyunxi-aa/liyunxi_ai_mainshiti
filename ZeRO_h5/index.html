🧩 ZeRO · 零冗余优化器

将优化器状态、梯度、参数分片到不同设备，消除数据并行中的冗余存储，使显存占用随设备数量线性减少

1. 问题：数据并行的显存冗余

在标准数据并行 (Data Parallel) 中，每张 GPU 都持有完整的模型（参数、梯度、优化器状态）。 以 Adam 优化器训练 7.5B 参数模型为例：fp16 参数占 15GB，fp32 优化器状态（m + v + param32）占 90GB， 梯度占 15GB — 单卡需要 120GB 显存，而 A100 仅 80GB。即使数据能分 8 份并行计算， 显存冗余并不会减少 — 每一张卡都重复存着完全相同的参数/梯度/优化器状态。

📐 单卡显存分解 (Adam 优化器, Ψ 参数量)

💡 核心矛盾：数据并行让计算并行化了，但显存并没有并行化。 每张卡都在重复存储完全相同的模型状态 — 这是巨大的浪费。 ZeRO 的核心思想：既然大家都存一样的东西，不如每人只存 1/Nd。

2. ZeRO 三阶段递进优化

ZeRO（Zero Redundancy Optimizer）由 Microsoft DeepSpeed 团队提出， 将模型状态分为三类：优化器状态、 梯度、 参数， 每个阶段额外分片一类，递进减少显存占用。

🔸 ZeRO-1 优化器状态分片

Pos — Optimizer State Partitioning

  • 每张卡仍存 完整参数 + 完整梯度
  • 优化器状态切成 Nd 份，每卡仅持 1/Nd
  • 更新时各自更新自己负责的部分
  • 显存节省：~4×（优化器状态占大头）

🔹 ZeRO-2 + 梯度分片

Pos+g — 额外分片梯度

  • 每张卡仍存 完整参数
  • 优化器状态 + 梯度都切成 Nd 份
  • 反向传播后梯度 Reduce-Scatter 到各自持有者
  • 显存节省：~8×

🟢 ZeRO-3 + 参数分片

Ppos+g+p — 额外分片参数

  • 三类模型状态 全部分片
  • 前向/反向需要参数时 All-Gather 收集
  • 不需要的参数可立即释放
  • 显存节省：与 Nd 线性相关
💡 递进关系：ZeRO-1 → ZeRO-2 → ZeRO-3 逐步增加分片粒度。 通信量也随之递增（ZeRO-1 仅在更新时通信，ZeRO-3 每次前向/反向都需要 All-Gather 参数）。 实践中 ZeRO-2 是性价比最高的选择，ZeRO-3 用于极端大模型。

4. 通信模式 — 按需聚合，即时释放

ZeRO 的核心通信原语是 All-Gather（收集完整数据）和 Reduce-Scatter（归约后分散）。 不同阶段触发通信的时机不同：ZeRO-1/2 仅训练步骤边界通信，ZeRO-3 每次前向/反向层都需要通信。

💡 通信 vs 计算重叠：ZeRO-3 的 All-Gather 可以在计算当前层时预取下一层参数， 实现通信与计算的重叠（Pipelining）。这也是为什么 ZeRO-3 的额外通信开销在大多数场景下可被隐藏。
