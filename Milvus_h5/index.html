什么是 Milvus？

Milvus 是由 Zilliz 开源的云原生向量数据库，专为 embedding 向量存储、索引与大规模相似性搜索而设计。 它支持万亿级向量数据管理，提供毫秒级查询延迟，被广泛用于 RAG（检索增强生成）、推荐系统、图像搜索、分子相似性搜索等场景。 Milvus 在 LF AI & Data 基金会（Linux 基金会子组织）中处于毕业阶段，GitHub 40k+ Stars。

🎯 核心特性

  • 存储计算分离：无状态 Proxy + 有状态存储，独立扩缩
  • 多种索引：11 种 ANN 索引覆盖不同场景
  • 混合搜索：Dense + Sparse 向量联合检索 + 标量过滤
  • 多语言 SDK：Python / Java / Go / Node.js / C#
  • 云原生架构：K8s 原生，支持水平扩展

💡 为什么需要专用向量数据库？传统数据库（MySQL/PostgreSQL）对向量近邻搜索支持极差（全表扫描 O(N)）；而 Faiss 只是算法库， 缺少持久化、分布式、多租户等能力。向量数据库 = ANN 索引引擎 + 持久化存储 + 分布式系统 + 标量过滤 + 数据管理 API。

💡 写入路径：Proxy → 消息队列（WAL）→ Data Node（内存 → Flush 到 S3）→ Index Node（异步构建索引）。 读取路径：Proxy → Query Node（从 S3 加载 Segment + 索引 → 执行检索 → 返回 Top-K）。 写入与查询完全解耦，索引构建不影响检索性能。

📌 核心概念

Partition（分区）

Collection 的物理子集，按 Partition Key 自动分片写入。查询时指定分区可大幅减少搜索范围，实现数据隔离。

Segment（段）

Milvus 内部的最小数据单元。Growing Segment（内存中，可写入）→ Flush → Sealed Segment（持久化到 S3，可建索引）。

Shard（分片）

Collection 的逻辑分片，数据按主键哈希分配到不同 Shard。每个 Shard 由独立的 Data Node 处理，提升写入吞吐。

Consistency（一致性）

四种级别：Strong / Session / Bounded / Eventually，在一致性与延迟之间做权衡。

相似度度量：5 种距离公式

Milvus 支持 5 种向量相似度度量方式，覆盖浮点向量和二进制向量。选择合适的度量方式对检索精度至关重要。

📐 Euclidean Distance (L2) — 欧氏距离

📐 Inner Product (IP) — 内积

📐 Cosine Similarity — 余弦相似度

📐 Hamming Distance — 汉明距离

📐 Jaccard Distance — 杰卡德距离

度量类型Milvus 枚举值适用向量分数语义典型场景
L2MetricType.L2FLOAT_VECTOR越小越相似图像检索、通用 embedding
IPMetricType.IPFLOAT_VECTOR越大越相似需要归一化的场景（等价 COSINE）
COSINEMetricType.COSINEFLOAT_VECTOR越大越相似文本语义相似度（推荐）
HAMMINGMetricType.HAMMINGBINARY_VECTOR越小越相似图像哈希、指纹匹配
JACCARDMetricType.JACCARDBINARY_VECTOR越小越相似集合相似度、分子指纹
💡 关键选择：L2 vs IP vs COSINE
• 如果 embedding 模型已经输出 L2 归一化向量（如 text-embedding-3-small），则 IP 与 COSINE 等价，推荐使用 IP（计算更快，无需除模长）。
• 如果 embedding 模长有意义（如某些视觉特征），使用 COSINE 只关注方向。
• 图像检索常用 L2；文本语义检索推荐 COSINE。

索引类型：11 种 ANN 索引全景

Milvus 支持业界最丰富的索引类型集合。不同的索引在构建速度、查询延迟、召回率、内存/磁盘占用之间做不同权衡。

IVF_FLAT K-Means 聚类 + 倒排索引 中中高❌ 中等数据集，高召回需求
IVF_SQ8 IVF + 8-bit 标量量化 低中中高❌ 内存受限场景
IVF_PQ IVF + 乘积量化（PQ） 极低中中❌ 大规模数据，极致内存压缩
SCANN 各向异性量化 + IVF 低快高❌ Google ScaNN 实现，高维 + 高召回
HNSW 分层可导航小世界图 高极快极高❌ 低延迟优先，内存充足时首选
DISKANN Vamana 图 + SSD 优化 极低中高✅ 必须 SSD 十亿级数据，低内存预算
GPU_IVF_FLAT IVF + GPU 并行暴力 中批量极快100%❌ GPU 加速批量查询

💡 选型口诀： • 内存充足 + 低延迟 → HNSW（最平衡的选择）
• 内存受限 + 大规模 → IVF_PQ 或 SCANN
• 十亿级 + 磁盘为主 → DISKANN
• 需要 100% 精确 → FLAT 或 GPU_IVF_FLAT
• 二进制向量 → BIN_IVF_FLAT
• 没有银弹——始终在召回率 vs 延迟 vs 内存三者间做权衡。

检索方式全解：7 种搜索方法

Milvus 提供丰富的检索方式，远超简单的 "Top-K 近邻"。下面是完整的 7 种检索方法——从基础 ANN 到高级混合搜索，每种都附有 Python 示例代码。

🔹 方法 1：基本 ANN 搜索（Top-K Nearest Neighbor）

最基础的向量检索——给定一个 Query 向量，返回距离最近的 K 个结果。这是所有其他检索方法的基础。

核心参数： limit（Top-K 数量）、 offset（分页偏移）、 output_fields（返回的标量字段）、 search_params（索引查询参数如 nprobe、ef）

🔹 方法 2：范围搜索（Range Search）

不限制返回数量，而是返回所有距离在指定阈值内的向量。支持单边范围（距离 ≤ r）和双边范围（r1 ≤ 距离 ≤ r2）。

使用场景：相似度阈值过滤（如"找出所有相似度 > 0.9 的文档"）、基于半径的去重、异常检测。

核心参数： radius（外圈半径）、 range_filter（内圈半径，用于双边范围）

🔹 方法 3：标量过滤搜索（Filtered Search / Attribute Filtering）

在向量检索的同时应用标量过滤条件——先过滤出满足条件的 Entity 子集，再在其中执行 ANN 搜索。这是生产环境中最常用的检索方式之一。

使用场景："2024年发表的论文中相似的内容"、"价格在 100-500 元间的相似商品"、"特定用户的相似历史记录"。

过滤表达式语法： filter='price > 100 and price < 500'、 filter='category in ["books","music"]'、 filter='tags like "sci%fi"'

🔹 方法 4：混合搜索（Hybrid Search — Dense + Sparse）

Milvus 2.4+ 的核心特性——同时使用稠密向量（Dense Embedding，语义匹配）和稀疏向量（Sparse Embedding，如 BM25/SPLADE，词汇匹配）进行联合检索。通过加权融合（WeightedRanker）或 RRF（Reciprocal Rank Fusion）合并两种信号。

使用场景：RAG 系统中需要兼顾语义理解和关键词精确匹配的场景——最接近真实的搜索引擎体验。

融合策略： WeightedRanker(0.7, 0.3)（加权融合，权重可调）、 RRFRanker(k=60)（排序融合，不依赖绝对分数）

🔹 方法 5：多向量搜索（Multi-Vector / Multi-Column Search）

一个 Collection 可以有多个向量字段（如 title_embedding + content_embedding）。多向量搜索用同一个 Query 的不同 Projection 在这些字段上分别检索，然后融合结果。

使用场景：多模态检索（文本+图片 embeddings 在同一 Entity 中）、不同粒度 embeddings（文档级 + 段落级）联合检索。

🔹 方法 6：分组搜索（Grouping Search）

按某个标量字段分组，在每个组内分别执行 ANN 搜索并返回每组 Top-K。保证结果多样性——不会因为某个主题的文档特别多而挤占其他主题的结果。

使用场景：不重复主题的推荐（"每个品类推荐 3 件商品"）、按文档类型分组检索、去重搜索。

核心参数： group_by_field（分组字段）、 group_size（每组返回数量）、 strict_group_size（不足时是否严格限制）

🔹 方法 7：迭代器搜索（QueryIterator / Search Iterator）

对于需要返回大量结果的搜索（如 K=10000），QueryIterator 提供流式迭代器接口，避免一次加载所有结果到内存。类似于关系型数据库的 Cursor。

使用场景：全量相似性去重（找出所有相似对）、大规模数据导出后的再处理、需要返回远超单次 limit 的结果。

使用方式： collection.query_iterator(batch_size=1000, ...) → 循环 iterator.next()
💡 检索方式选择决策树：
• 只需语义相似 Top-K → 基本 ANN 搜索
• 需要相似度阈值控制 → 范围搜索
• 需要标量条件 + 向量 → 过滤搜索
• 需要关键词 + 语义联合 → 混合搜索（Dense+Sparse）
• 需要结果多样性 → 分组搜索
• 需要多模态/多粒度 → 多向量搜索
• 需要海量结果（K > 10000） → 迭代器搜索
• 生产 RAG 推荐组合：混合搜索 + 标量过滤

Python SDK 完整示例

以下代码示例覆盖从连接 Milvus、创建 Collection、插入数据到全部 7 种检索方式的完整流程。使用 Milvus Standalone / Milvus Lite 可零依赖本地运行。

📌 环境准备 & 连接


# pip install pymilvus "pymilvus[model]"  # model 可选，内嵌 embedding 模型

from pymilvus import (
    MilvusClient, DataType, AnnSearchRequest,
    WeightedRanker, RRFRanker
)

# 连接 Milvus（Lite 模式：本地文件存储，无需 Docker）
client = MilvusClient("milvus_demo.db")
print("✅ Connected to Milvus")

📌 创建 Collection（含 Dense + Sparse 双向量字段）


# 先删除已存在的 Collection（如有）
client.drop_collection("demo_rag")

# 定义 Schema：PK + 标量字段 + Dense 向量 + Sparse 向量
schema = MilvusClient.create_schema(
    auto_id=False,
    enable_dynamic_field=True
)

schema.add_field(field_name="id", datatype=DataType.INT64, is_primary=True)
schema.add_field(field_name="text", datatype=DataType.VARCHAR, max_length=512)
schema.add_field(field_name="category", datatype=DataType.VARCHAR, max_length=64)
schema.add_field(field_name="year", datatype=DataType.INT64)
schema.add_field(field_name="dense_vec", datatype=DataType.FLOAT_VECTOR, dim=128)
schema.add_field(field_name="sparse_vec", datatype=DataType.SPARSE_FLOAT_VECTOR)

# 创建索引
index_params = client.prepare_index_params()
index_params.add_index(field_name="dense_vec",
    index_type="IVF_FLAT",
    metric_type="COSINE",
    params={"nlist": 128})
index_params.add_index(field_name="sparse_vec",
    index_type="SPARSE_INVERTED_INDEX",
    metric_type="IP")

client.create_collection(
    collection_name="demo_rag",
    schema=schema,
    index_params=index_params
)
print("✅ Collection created with Dense + Sparse vectors")

📌 插入模拟数据


import random, numpy as np

entities = []
for i in range(500):
    # 模拟 128 维 embedding
    vec = np.random.randn(128).astype(np.float32)
    vec = vec / np.linalg.norm(vec)  # L2 归一化（COSINE = IP）

    # 模拟稀疏向量（关键词匹配信号）
    sparse = {0: float(random.random()), 3: float(random.random()),
              7: float(random.random()), 15: float(random.random())}

    entities.append({
        "id": i,
        "text": f"文档内容片段 #{i:03d}  深度学习 向量数据库 RAG",
        "category": random.choice(["AI", "DB", "ML", "System"]),
        "year": random.choice([2022, 2023, 2024, 2025]),
        "dense_vec": vec,
        "sparse_vec": sparse,
    })

client.insert(collection_name="demo_rag", data=entities)
print(f"✅ Inserted {len(entities)} entities")

📌 检索 1：基本 ANN 搜索


query_vec = np.random.randn(128).astype(np.float32)
query_vec = query_vec / np.linalg.norm(query_vec)

results = client.search(
    collection_name="demo_rag",
    data=[query_vec],
    anns_field="dense_vec",
    limit=5,
    output_fields=["text", "category", "year"],
    search_params={"metric_type": "COSINE",
                   "params": {"nprobe": 16}}
)

for hit in results[0]:
    print(f"  id={hit['id']}, dist={hit['distance']:.4f}, "
          f"text={hit['entity']['text'][:30]}")

📌 检索 2：范围搜索


# 返回所有 COSINE 距离在 [0.1, 0.5] 范围内的向量（即相似度 0.5~0.9）
results = client.search(
    collection_name="demo_rag",
    data=[query_vec],
    anns_field="dense_vec",
    limit=100,               # 上限，范围搜索可在 limit 内返回满足条件的结果
    search_params={
        "metric_type": "COSINE",
        "params": {"radius": 0.5,       # 外圈：距离 ≤ 0.5
                   "range_filter": 0.1}, # 内圈：距离 ≥ 0.1
    },
    output_fields=["text"]
)
print(f"✅ Range search: {len(results[0])} results in [0.1, 0.5]")

📌 检索 3：标量过滤搜索


# 只在 category="AI" 且 year ≥ 2024 的数据中检索
results = client.search(
    collection_name="demo_rag",
    data=[query_vec],
    anns_field="dense_vec",
    limit=5,
    filter='category == "AI" and year >= 2024',
    output_fields=["text", "category", "year"],
    search_params={"metric_type": "COSINE",
                   "params": {"nprobe": 16}}
)
for hit in results[0]:
    e = hit['entity']
    print(f"  id={hit['id']}, cat={e['category']}, year={e['year']}, dist={hit['distance']:.4f}")

📌 检索 4：混合搜索（Dense + Sparse + WeightedRanker）


# 创建 Dense 搜索请求
dense_req = AnnSearchRequest(
    data=[query_vec],
    anns_field="dense_vec",
    param={"metric_type": "COSINE", "params": {"nprobe": 16}},
    limit=10
)

# 创建 Sparse 搜索请求（模拟词汇匹配信号）
sparse_query = {0: 0.8, 3: 0.6, 7: 0.4}
sparse_req = AnnSearchRequest(
    data=[sparse_query],
    anns_field="sparse_vec",
    param={"metric_type": "IP"},
    limit=10
)

# 加权融合：Dense 权重 0.7, Sparse 权重 0.3
results = client.hybrid_search(
    collection_name="demo_rag",
    reqs=[dense_req, sparse_req],
    ranker=WeightedRanker(0.7, 0.3),
    limit=5,
    output_fields=["text", "category"]
)
for hit in results[0]:
    print(f"  id={hit['id']}, score={hit['distance']:.4f}, cat={hit['entity']['category']}")

📌 检索 4b：混合搜索 · RRF 排序融合


# 使用 RRF 替代加权——不依赖绝对分数，只依赖排名
results = client.hybrid_search(
    collection_name="demo_rag",
    reqs=[dense_req, sparse_req],
    ranker=RRFRanker(k=60),   # k 为平滑常数，通常 60
    limit=5,
    output_fields=["text"]
)
print("✅ RRF hybrid search done")

📌 检索 5：多向量搜索（同一 Query 对多个向量字段检索）


# 场景：Collection 有 title_embedding 和 content_embedding 两个向量字段
# 对同一个 Query 的两个不同 Projection 分别检索

# 方法 A：分别对不同字段搜索 + 融合
req_title = AnnSearchRequest(
    data=[query_vec],
    anns_field="title_embedding",  # 对标题 embedding 搜索
    param={"metric_type": "COSINE", "params": {"nprobe": 16}},
    limit=10
)
req_content = AnnSearchRequest(
    data=[query_vec],
    anns_field="content_embedding", # 对正文 embedding 搜索

    limit=10

    collection_name="demo_multi_vec",

    limit=5,

print("✅ Multi-vector search done")

📌 检索 6：分组搜索（Grouping Search）


# 按 category 分组，每组返回 2 个最相似的文档
results = client.search(
    collection_name="demo_rag",
    data=[query_vec],
    anns_field="dense_vec",
    limit=8,               # 总返回上限
    group_by_field="category",   # 👈 分组字段
    group_size=2,              # 👈 每组返回 2 个
    strict_group_size=True,     # 严格保证每组恰好 group_size 个（除非该组不足）
    output_fields=["text", "category"],
    search_params={"metric_type": "COSINE",
                   "params": {"nprobe": 16}}
)

# 按分组打印结果
for hit in results[0]:
    e = hit['entity']
    print(f"  [{e['category']}] id={hit['id']}, dist={hit['distance']:.4f}")

📌 检索 7：迭代器搜索（大批量结果流式获取）


# 使用 QueryIterator 流式获取大量结果
# 适用场景：需要超过 limit 上限的结果（如 K=10000）

iterator = client.query_iterator(
    collection_name="demo_rag",
    batch_size=100,              # 每次 next() 返回 100 条
    expr='category == "AI"',       # 可选：标量过滤
    output_fields=["text", "year"],
    limit=1000,                  # 总获取上限
)

total = 0
while True:
    batch = iterator.next()
    if not batch:
        break
    total += len(batch)
    print(f"  Batch: {len(batch)} rows, total so far: {total}")

print(f"✅ Iterator done, total fetched: {total}")
iterator.close()

Milvus 检索性能受多种因素影响——从索引选择到系统配置，以下是关键调优维度。

📌 系统级调优参数

参数级别默认值影响调优建议
shards_numCollection1写入并行度写入量大时设为 2~4；每 Shard 消耗一个 Data Node
segment_row_limitCollection1M每个 Segment 最大行数增大可减少 Segment 数量，降低元数据开销
nprobeSearch8召回率 + 延迟需要更高召回时增大；在线调优可动态平衡
efSearch (HNSW)64召回率 + 延迟范围 [k, 32768]；增大 2× 约增加 10% 延迟
graceful_timeDelete—删除一致性窗口可接受短时不一致则设大（提升性能）
consistency_levelSearch/QueryBounded一致性 vs 延迟可容忍旧数据设 Eventually；需强一致设 Strong
💡 调优金字塔（自底向上）：
Layer 1 硬件：足够的 RAM（向量数据量 × 1.5~2×）、SSD（如需磁盘索引）、GPU（批量高吞吐）
Layer 2 索引：选对索引类型 → 80% 问题解决；调整 nlist/M → 微调
Layer 3 查询参数：nprobe/ef → 线上动态可调，成本最低的调优手段
Layer 4 系统配置：Shard 数、Segment 大小、一致性级别 → 影响吞吐和稳定性
Layer 5 数据设计：维度选择、归一化、Partition 分区策略 → 基础级别影响
