₿ Bitcoin · 比特币协议深度解析

从区块数据结构、Merkle 树、UTXO 模型、椭圆曲线密码学，到 PoW 共识与 SPV 轻验证——拆解中本聪白皮书的每一层设计。

1. 比特币系统全景

比特币是首个去中心化数字货币，由 Satoshi Nakamoto 于 2008 年提出，2009 年上线。 其核心创新在于用 PoW（Proof of Work）工作量证明 解决了分布式系统中的拜占庭将军问题，无需中心化机构即可达成共识。 每约 10 分钟产生一个区块，总量上限 2100 万枚，每 210,000 个区块（约 4 年）发生一次"减半"。

2. 区块链数据结构

区块链是一个单向链表，每个区块通过包含前一区块的哈希值形成不可篡改的链条。 区块由 区块头（80 字节） 和 交易列表 两部分组成。

📦 区块头 (Block Header) — 80 字节

// C++ 风格结构体表示 struct CBlockHeader { int32_t nVersion; // 4 字节 — 版本号 uint256 hashPrevBlock; // 32 字节 — 前一区块哈希 uint256 hashMerkleRoot;// 32 字节 — Merkle 树根 uint32_t nTime; // 4 字节 — Unix 时间戳 uint32_t nBits; // 4 字节 — 压缩难度目标 uint32_t nNonce; // 4 字节 — PoW 随机数 }; // 总计 80 字节

💡 为什么 80 字节如此精妙？ 区块头 = 80 字节正好适配一个 SHA-256 压缩函数的输入块（64 字节 + 填充），使得挖矿时 SHA-256² 计算极为高效。 仅改变 nonce 就足以扰动整个哈希输出，这是 PoW 的设计基础。

3. Merkle 树 — 交易的密码学摘要

Merkle 树将区块中所有交易的两两哈希逐层归约为一个 32 字节的 Merkle 根（Merkle Root）。 这使得轻节点只需区块头 + Merkle Proof 即可验证某笔交易是否在区块中，无需下载完整区块。

💡 Merkle Proof 验证仅需 O(log₂N) 个哈希：一笔交易在包含 2048 笔交易的区块中，验证其存在仅需 11 个中间哈希值（约 352 字节），而非下载整个区块（~1-4 MB）。 这正是 SPV（Simple Payment Verification） 轻节点的核心原理。

4. 交易与 UTXO 模型

比特币的"余额"不是存在某个地址里，而是由 UTXO（Unspent Transaction Output，未花费交易输出） 集合决定。 每笔交易 消费旧的 UTXO，并 创建新的 UTXO——这类似于现金交易中的找零模型。

🔐 锁定脚本与解锁脚本

// P2PKH (Pay-to-PubKey-Hash) — 最常见的交易类型 // 锁定脚本 (ScriptPubKey) — 放在输出上 OP_DUP OP_HASH160 <PubKeyHash> OP_EQUALVERIFY OP_CHECKSIG // 解锁脚本 (ScriptSig) — 放在输入上，消费时提供 <Signature> <PublicKey> // 验证时，两段拼接执行: <Sig> <PubKey> OP_DUP OP_HASH160 <PubKeyHash> OP_EQUALVERIFY OP_CHECKSIG
💡 UTXO vs 账户模型：比特币的 UTXO 模型天然支持并行验证（各 UTXO 独立），隐私性更好。 以太坊的账户模型更易编写智能合约，但需要全局状态树。两者各有取舍。

5. 椭圆曲线密码学 (ECDSA on secp256k1)

比特币使用 secp256k1 曲线上的 ECDSA（椭圆曲线数字签名算法）来确保只有私钥持有者才能花费对应的 UTXO。 secp256k1 是 Koblitz 曲线，参数特殊设计为高效计算优化。

📐 secp256k1 曲线参数

🔑 密钥生成

// 比特币地址生成流程 Private Key (256-bit 随机数) k ↓ ECDSA 公钥推导 Public Key (secp256k1 点, 33/65 字节) K = k·G ↓ SHA-256 H₁ = SHA256(K) ↓ RIPEMD-160 H₂ = RIPEMD160(H₁) // 20 字节 ↓ Base58Check 编码 Address (1... 开头) // P2PKH 地址

✍️ 签名与验证

💡 为什么 SHA-256 之后还要 RIPEMD-160？ 双重哈希增加了抗碰撞安全性，同时将公钥哈希压缩到 20 字节（160 位）， 使得比特币地址更短。即使 SHA-256 被部分攻破，RIPEMD-160 仍提供第二层防护。

6. PoW 工作量证明与挖矿

矿工不断改变 nonce（以及 extraNonce、时间戳），对区块头做 SHA-256²（双重 SHA-256）， 直到哈希值小于当前难度目标。这是纯粹的随机尝试过程，符合 伯努利试验 分布。

📊 难度调整机制

每 2016 个区块（约 2 周），网络自动调整难度，使得平均出块时间回归 10 分钟。

💡 PoW 的本质是"燃烧能量换取安全性"：攻击者需要掌握 >50% 全网算力才能双花，而诚实矿工的总算力已超过全球 Top 500 超算总和的数十万倍。 任何对历史的篡改都需要完全重做从那之后所有区块的 PoW，算力成本指数级增长。

7. SPV 轻节点与 Merkle Proof 验证

SPV（Simple Payment Verification） 节点仅存储区块头（~80 字节/块，每年约 4.2 MB）， 通过向全节点请求 Merkle Proof 来验证特定交易是否被确认。

🔍 交互式 Merkle Proof 验证

点击任意绿色叶子节点（交易），生成验证该交易所需的 Merkle Proof 路径。

💡 SPV 安全性：SPV 节点无法独立验证交易是否双花（需要全节点），但 Merkle Proof 密码学保证了"交易在区块中"这一事实。 结合 工作量证明链（最长链 = 最多累计难度），SPV 节点能确认交易已被网络接受。

8. 网络共识与分叉

比特币网络采用 Nakamoto 共识——最长链（实际上是 最多累计工作量 的链）为有效链。 当两个矿工几乎同时发现新区块时，网络暂时分叉，随后通过"最长链胜出"规则解决。

💡 "6 次确认"的由来：中本聪在白皮书中计算了攻击者在落后 z 个区块后追上主链的概率（遵循泊松分布）。 假设攻击者掌握 10% 算力，6 次确认（z=6）可使双花成功概率降至约 0.024%，商业上可接受。参见 [[bitcoin-whitepaper]] 第 11 节。
