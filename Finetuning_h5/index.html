🔧 大模型微调 · RLHF & LoRA

从全量微调到参数高效微调（PEFT），从 SFT 到 RLHF 对齐训练——深入理解现代 LLM 训练范式的核心原理与交互式可视化

1. 大模型微调全景：全量 vs PEFT

预训练大模型获得通用语言能力后，需要微调（Fine-tuning）使其适配特定任务。 全量微调更新所有参数，显存和计算开销巨大；参数高效微调（PEFT）仅更新少量参数， 使单卡即可微调 7B-70B 级别模型。

方法 可训练参数量 显存需求 (7B) 训练速度 推理开销 代表作
全量微调 100% (7B) ~56 GB (fp16) 慢 无额外开销 GPT-3 Fine-tune
Adapter ~1-5% ~15 GB 中等 有推理延迟 AdapterHub
Prefix Tuning ~0.1% ~14 GB 快 轻微开销 P-Tuning v2
LoRA ~0.1-1% ~14 GB 快 可合并无开销 LoRA, QLoRA
💡 核心思想：预训练模型已经学到了丰富的特征表示，微调所需的"任务适配"可能只需要低秩的权重调整。 LoRA 正是基于这一假设，将权重增量 ΔW 分解为两个低秩矩阵的乘积。

2. LoRA · 低秩适应 — 两个小矩阵撬动大模型

LoRA 的核心思想：冻结预训练权重 W₀ ∈ Rd×k，在其旁路注入可训练的 低秩分解矩阵 B ∈ Rd×r 和 A ∈ Rr×k（r ≪ min(d,k)）。 前向传播变为 h = W₀x + BAx，只有 B 和 A 参与梯度更新。

📐 LoRA 核心公式

💡 参数量对比：原始 W₀ 大小为 d×k；LoRA 的 B(d×r) + A(r×k) = r·(d+k) 个参数。 当 r=16, d=k=4096 时，LoRA 仅需 131K 参数 vs 原始 16.8M——压缩 128 倍。 QLoRA 进一步将 W₀ 量化为 4-bit NormalFloat，使得在 48GB GPU 上即可微调 65B 模型。

3. RLHF 三阶段对齐训练

RLHF（Reinforcement Learning from Human Feedback）是 InstructGPT / ChatGPT 背后的核心对齐技术。 通过人类偏好反馈微调模型，使其输出更符合人类的价值观和意图。 整个流程分为三个关键阶段——

1→ 2→ 3
阶段一

🎓 SFT · 监督微调

用高质量人工标注的（指令, 回答）对微调预训练模型。 模型学习遵循指令格式，获得基本的指令遵循能力。

数据规模 ~10K-100K 条
阶段二

🏆 奖励模型训练

用人类偏好排序数据训练奖励模型 r(x,y)。 对同一 prompt 的两个回答，人类标注哪个更好，模型学习评分。

数据格式 (prompt, 胜, 负) 对
阶段三

🎯 PPO 强化学习

用奖励模型作为 reward signal，通过 PPO 算法优化 SFT 模型。 加入 KL 惩罚防止模型偏离太远（reward hacking）。

优化目标 max E[r] − β·KL
💡 为什么需要 RLHF？直接使用人类标注数据做 SFT 存在分布不匹配——模型在训练时"背诵"标准答案， 但实际使用中会遇到大量分布外问题。RLHF 通过偏好排序 + 强化学习，让模型学会泛化"什么是好的回答"， 而非记忆特定答案。InstructGPT (1.3B) 通过 RLHF 在人类评估中击败了 175B 的 GPT-3。

4. 奖励模型 · Bradley-Terry 偏好建模

奖励模型将偏好排序转化为监督学习问题：对于 prompt x，给定一对回答 (yw, yl)（w=win 胜, l=lose 负）， 模型需要学习一个 标量评分函数 r(x, y)，使得胜者得分更高。 这通常通过 Bradley-Terry 模型建模胜负概率。

📐 Bradley-Terry 偏好模型 & 损失函数

💡 奖励模型的训练数据：标注者看到同一个 prompt 的多个模型回答，进行排序（而非直接打分）。 排序比打分更容易、更一致——比较比绝对值更可靠。 Anthropic 的 Preference Model 和 OpenAI 的 RM 都采用类似策略。 损失函数本质上是逻辑回归：最大化 P(win > lose) 的对数似然。

5. PPO · 近端策略优化 + KL 约束

RLHF 的最后一阶段使用 PPO（Proximal Policy Optimization） 算法，将语言模型视为策略 π(y|x)。 奖励模型提供 reward，同时加入 KL 散度惩罚防止模型为追求高分而输出无意义文本（reward hacking）。 优化目标是三者的加权平衡。

📐 PPO + KL 优化目标

// PPO RLHF 训练循环 (简化) for each batch of prompts x: y = π_θ(x) // 当前策略生成回答 r = r_φ(x, y) // 奖励模型打分 kl = log(π_θ(y|x)/π_ref(y|x)) // KL 散度 vs 参考策略 (SFT 模型) // 价值函数 V(x) 估计期望回报，计算优势 A = r - V(x) advantage = r - β·kl - V(x) // PPO Clipped 损失：限制更新幅度，防止策略崩溃 ratio = π_θ(y|x) / π_θ_old(y|x) loss = -min(ratio·advantage, clip(ratio, 1-ε, 1+ε)·advantage) θ = θ - lr · ∇_θ loss // 梯度下降
💡 KL 惩罚为什么关键？如果不加 KL 约束，策略可能学会输出乱码或重复文本去"骗取"高奖励—— 即 Reward Hacking（奖励攻击）。奖励模型只在训练分布内可靠，OOD 的输出评分毫无意义。 KL 惩罚强制模型不要偏离 SFT 模型太远，相当于在可信区域内优化。β 越大，模型越保守。

6. 对齐方法全景对比：RLHF · DPO · SFT

近年来出现了多种对齐训练方法，从经典的三阶段 RLHF 到更简化的 DPO（直接偏好优化）， 再到基于排序的 KTO、ORPO 等。不同方法在复杂度、稳定性、数据效率上各有取舍。

方法 需要 RM？ 需要 RL？ 数据格式 训练稳定性 代表工作
SFT 否 否 (x, y) 示范 高 Alpaca, Vicuna
RLHF 是 (需要) 是 (PPO) 偏好排序 低 (需调参) InstructGPT, ChatGPT
DPO 否 (隐式) 否 偏好对 (yw, yl) 高 DPO, Zephyr
KTO 否 否 单样本 (±标注) 高 Kahneman-Tversky
ORPO 否 (联合) 否 偏好对 高 ORPO (单阶段)

📐 DPO — 绕过奖励模型的直接偏好优化

💡 DPO 简化了什么？省去了单独训练 Reward Model 的过程，也不再需要复杂的 PPO 强化学习循环。它证明了：奖励建模和策略优化其实是同一个硬币的两面，可以直接用奖励函数的目标去解析求解策略模型的最优更新方向。
