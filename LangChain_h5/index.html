⛓️ LangChain · LLM 应用开发框架

通过 Chain/Runnable 抽象将 LLM、工具、检索器、记忆等组件编排为可组合的管道，支持 LCEL 声明式语法与 Agent 自主决策循环

1. 核心抽象：Runnable 协议

LangChain 的一切都围绕 Runnable 协议展开。任何组件（LLM、提示词模板、检索器、工具）都实现了统一的 .invoke() / .stream() / .batch() 接口。这使得组件可以像搭积木一样任意组合， 并通过 LCEL（LangChain Expression Language） 的 | 管道符串联。

📐 Runnable 核心接口

💡 统一接口的力量：因为所有组件都遵循 Runnable 协议，你可以把 LLM 的输出直接 pipe 给下一个组件， 也可以用 .with_retry() 给任何组件加上重试、用 .with_fallbacks() 加上降级方案。 这是 LangChain 可组合性的基石。

2. LCEL 管道语法 — 构建处理链

LCEL 使用 Python 的 | 运算符将 Runnable 串联起来： chain = prompt | model | output_parser。 数据从左到右流动，每个组件的输出成为下一个组件的输入。LangChain 自动处理 中间结果的传递、异步调用、流式输出和并行化。

# LCEL: 用管道构建 LLM 应用
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_template(
    "用{language}解释：{concept}"
)
model = ChatOpenAI(model="gpt-4")
parser = StrOutputParser()

# ⬇ LCEL 管道 — 数据从左到右流动
chain = prompt | model | parser

# 调用方式完全统一
result = chain.invoke({"language": "Python", "concept": "闭包"})
async for chunk in chain.astream(...):
    print(chunk, end="")  # 流式逐 token 输出
💡 管道即类型安全的数据流：LCEL 会自动检查每个组件的输入/输出 schema， 在构建时（而非运行时）发现类型不匹配。此外，chain 本身也是 Runnable — 你可以将它作为子组件嵌入更大的 chain 中，形成层级化组合。

3. RAG 检索增强生成 — LangChain 的旗舰应用

RAG（Retrieval-Augmented Generation）是 LangChain 最常见的用例。 流程分为 索引阶段（离线）和 查询阶段（在线）： 文档 → 切分 → 嵌入 → 向量库 → 检索 → 注入提示词 → LLM 生成。

📐 RAG 两阶段流程

💡 为什么 RAG 如此重要：LLM 的知识截止于训练日期，且无法访问私有数据。 RAG 将检索系统与生成模型解耦：向量库可以随时更新（无需微调模型）， 并能通过 metadata 过滤实现权限控制和时间范围筛选。 LangChain 提供了从 Document Loader → Text Splitter → Embeddings → VectorStore → Retriever 的完整工具链。

4. Agent 工具调用 — ReAct 自主决策循环

Agent 是 LangChain 中最强大的模式：LLM 不再只是"回答问题"，而是自主决定 调用哪个工具、以什么参数调用、何时停止。经典的 ReAct（Reasoning + Acting） 模式让模型交替进行"思考→行动→观察"的循环，直到得出最终答案。

📐 ReAct Agent 循环


# LangChain Agent 定义
from langchain_openai import ChatOpenAI
from langgraph.prebuilt import create_react_agent

tools = [search_tool, calculator_tool, weather_tool]

agent = create_react_agent(
    model=ChatOpenAI(model="gpt-4"),
    tools=tools,
)

# Agent 自主决策循环：
# Thought → Action → Observation → Thought → ... → Final Answer
result = agent.invoke({
    "messages": ["北京今天天气怎么样？用这个温度计算华氏度"]
})
# Agent 会：1) 调用 weather_tool 获取气温
#         2) 调用 calculator_tool 转换华氏度
#         3) 返回自然语言答案
💡 Agent ≠ Chain：Chain 的执行路径是预定义的（编译时确定）， 而 Agent 的执行路径是动态的（运行时由 LLM 决定）。 Agent 可以调用工具的结果影响下一步决策，形成真正的自主循环。 LangGraph 进一步将 Agent 循环实现为状态图（StateGraph），使循环可检查点保存、可中断、可回溯。

5. LangChain 组件生态全景

LangChain 围绕 LLM 应用开发提供了完整的组件矩阵。 每个组件类别都有多个实现（与不同厂商/后端集成），且都遵循 Runnable 协议。

组件类别 核心职责 典型实现
Chat Models 接收消息列表，返回 AI 消息 ChatOpenAI, ChatAnthropic, ChatGoogle, ChatOllama
LLMs 接收文本字符串，返回文本 OpenAI, Anthropic, HuggingFacePipeline
Prompts 模板化提示词构建 ChatPromptTemplate, MessagesPlaceholder, FewShot
Document Loaders 从各种来源加载文档 PyPDF, WebBase, CSV, Notion, GitHub, S3
Text Splitters 将长文档切分为语义块 RecursiveCharacter, Markdown, Code, Semantic
Embeddings 将文本转为稠密向量 OpenAIEmbeddings, HuggingFaceEmbeddings, Cohere
Vector Stores 存储和检索向量 Chroma, Pinecone, Weaviate, Milvus, FAISS, Qdrant
Retrievers 给定查询，返回相关文档 VectorStoreRetriever, MultiQuery, Self-Query, MMR
Tools LLM 可调用的外部功能 @tool 装饰器, StructuredTool, DuckDuckGo, API 封装
Memory 跨对话轮次的状态管理 ConversationBuffer, Summary, TokenBuffer, VectorStore
Callbacks 生命周期钩子与可观测性 LangSmith tracing, 自定义回调, 成本追踪
💡 LangChain 的定位演变：LangChain 最初是一个"万能框架"，试图集成一切。 2024 年后，LangChain 团队将其拆分为：langchain-core（核心抽象）、 langchain-community（社区集成）、langgraph（Agent 编排）、 LangSmith（可观测性平台）。这种模块化让开发者可以按需引入，避免依赖膨胀。
